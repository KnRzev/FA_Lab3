## Задание 1

`task01.c` переводит целое число в систему счисления с основанием 2^r,
где r от 1 до 5. Используются основания 2, 4, 8, 16, 32 и цифры `0–9`, `A–V`.
Поддерживается весь диапазон `long long`, включая `LLONG_MIN`, отрицательные числа и ноль.

```c
Status to_base_power_of_two(long long number, unsigned int r,
                            char *buffer, size_t capacity);
```

Результат записывается в переданный буфер, функция возвращает статус выполнения.
Буфер должен содержать не менее `capacity` доступных для записи байт.
Достаточный размер для любого числа: `sizeof(unsigned long long) * CHAR_BIT + 2`.
При недостаточном размере буфера возвращается `STATUS_BUFFER_TOO_SMALL`,
выходная строка очищается. Нулевой указатель, нулевая ёмкость и r вне диапазона 1–5
считаются недопустимыми аргументами.

В функции перевода и её вспомогательных функциях отсутствуют арифметические
операции, включая `++` и `--`. Младшая цифра выделяется битовой маской,
затем число сдвигается на r бит. Рекурсия записывает старшие цифры первыми.
Увеличение позиции и получение модуля отрицательного числа выполняются
сложением через XOR, AND и перенос. Арифметика используется только отдельно:
при разборе десятичного ввода и в демонстрационной части.

Глобальных переменных, `errno`, `goto` и принудительного завершения из
вспомогательных функций нет. Вычисления отделены от ввода и вывода.
Динамическая память не используется. Код написан без комментариев.

## Задание 2

`task02.c` определяет максимальное число докладов, которые можно провести
в k равнозначных залах за один день. Доклад не прерывается и не переносится.
Окончание одного доклада может совпадать с началом следующего в том же зале.

```c
typedef struct {
    size_t id;
    unsigned int start_time;
    unsigned int finish_time;
} Talk;

Status max_talk_count(const Talk *talks, size_t count,
                      size_t hall_count, size_t *result);
```

В структуре время хранится в минутах от начала суток: от 0 до 1439.
Функция возвращает статус, количество выбранных докладов записывает
в `result`. Массив должен содержать `count` доступных элементов;
его содержимое не меняется. Числа заявок и залов должны быть положительными,
идентификаторы — положительными и уникальными, начало — строго раньше окончания.
При ошибке `result` равен нулю, если передан ненулевой указатель результата.

Алгоритм сначала проверяет уникальность идентификаторов на отсортированной
копии массива, затем сортирует заявки по возрастанию времени окончания.
Для очередной заявки выбирается зал, который освободился как можно позже,
но не позже начала доклада. Если такого зала нет, заявка пропускается.
Раннее окончание позволяет раньше освободить зал, а выбор последнего
подходящего времени освобождения сохраняет более ранние свободные залы
для докладов, которые начинаются раньше, но заканчиваются позже текущего.

Вместо отдельного элемента для каждого зала используется массив из 1440
счётчиков: сколько залов имеют данное время освобождения. Изначально залы
свободны с 00:00. При назначении доклада один счётчик уменьшается,
а счётчик времени его окончания увеличивается. Количество залов для вычисления
ограничивается числом заявок, поэтому даже очень большое k не требует
дополнительной памяти.

Сложность: O(n log n + 1440n) по времени, O(n + 1440) по памяти.
Все операции выделения памяти проверяются; память освобождается и при ошибках.
Ввод и вывод отделены от вычисления расписания.

## Задание 3

`task03.c` читает файл в бинарном режиме, строит префиксный код Хаффмана
для значений байтов 0–255 и оценивает размер закодированного содержимого.
Путь к файлу передаётся единственным аргументом командной строки.

Отчёт содержит таблицу `Byte Frequency Code`, упорядоченную по значению
байта, размер исходного файла в байтах, размер закодированных данных в битах
и байтах, экономию в процентах. Служебные данные для хранения дерева или
таблицы кодов в оценку не включаются. Программа выводит оценку и таблицу;
архивный файл не создаётся.

Основная вычислительная функция:

```c
Status analyze_frequencies(const unsigned long long frequencies[256],
                            HuffmanResult *result);
```

`frequencies` должен указывать на массив из 256 элементов, `result` —
на доступный объект `HuffmanResult`. Функция не выполняет ввод и вывод,
не меняет частоты и возвращает статус. При успехе результат содержит
коды, их длины и рассчитанные размеры. При ошибке содержимое результата
не следует использовать.

Чтение файла, вычисления и вывод отчёта разделены. Функция чтения считает
частоты блоками по 4096 байт; исходный файл целиком в памяти не хранится.
Дерево строится собственной бинарной минимальной кучей: два узла с наименьшими
частотами извлекаются, объединяются и возвращаются в кучу. Для равных весов
допускается любой порядок. Обход влево добавляет к коду 0, вправо — 1.

Куча содержит не более 256 указателей. Все узлы дерева (не более 511)
размещаются одним динамическим массивом, который освобождается после
формирования кодов, в том числе при ошибках. Длины кодов не превышают
255 бит; для каждого кода предусмотрены 256 символов с учётом конца строки.

Размер в битах равен сумме `частота * длина кода`. Размер в байтах
вычисляется делением на 8 с округлением вверх. Экономия вычисляется
как `100 * (1 - encoded_bytes / original_bytes)` в типе `long double`.
Если файл пустой, строк данных в таблице нет, размеры и экономия равны нулю.
Если встречается только одно значение байта, ему назначается код `0`.

Частоты и размеры хранятся как `unsigned long long`; переполнения при
сложении и умножении проверяются. Ошибки открытия, чтения, закрытия файла,
выделения памяти и вывода обрабатываются. Ввод может содержать любые байты,
включая нулевые; поддерживается платформа с восьмибитным байтом.
Глобальных переменных, `errno`, `goto`, принудительного завершения из
вспомогательных функций и комментариев в C-коде нет.

## Задание 4

`task04.c` содержит тип `String` и интерактивное почтовое отделение.

### Тип String

```c
typedef struct {
    char *data;
    int length;
} String;

Status string_create(const char *text, String *result);
Status string_destroy(String *string);
Status string_compare(const String *first, const String *second, int *result);
Status string_equal(const String *first, const String *second, int *result);
Status string_copy(const String *source, String *destination);
Status string_clone(const String *source, String **result);
Status string_concat(String *first, const String *second);
```

Перед первым использованием объект необходимо инициализировать: `String s = {0};`.
Пустая строка может иметь нулевой указатель и длину 0. Длина считается в элементах
`char`, без завершающего нуля; для UTF-8 это число байтов. Строка хранит собственную
копию данных. Размер ограничен `INT_MAX`. Нулевой байт внутри содержимого не допускается.

`string_compare` возвращает через параметр -1, 0 или 1: сначала сравнивается длина,
при равной длине — лексикографический порядок. `string_equal` возвращает 1 для
лексикографически равных строк, иначе 0. Все функции возвращают статус выполнения.

`string_create` и `string_copy` могут заменить содержимое уже инициализированного
объекта. Копии независимы. Самокопирование и конкатенация строки с самой собой
поддерживаются. При отказе выделения памяти прежнее содержимое сохраняется.

Для `string_clone` передайте указатель, изначально равный `NULL`. Функция выделяет
память и для структуры, и для её содержимого. Для удаления клона сначала вызовите
`string_destroy`, затем `free` для самой структуры. `string_destroy` освобождает
только внутренний массив, устанавливает указатель в `NULL`, длину — в 0.
Повторное удаление внутреннего содержимого допустимо.

### Почтовое отделение

`Address` содержит город, улицу, дом, корпус, квартиру и индекс. `Mail` содержит
адрес получателя, вес, идентификатор, время создания, время вручения и флаг доставки.
Все строковые поля имеют тип `String`. `Post` содержит указатель на адрес текущего
отделения и динамический массив посылок с количеством элементов и ёмкостью.

В условии не задан способ отличать фактическую доставку от истечения её срока.
Принята следующая договорённость: `delivery_time` — плановое время вручения,
а дополнительный флаг `delivered` отражает факт доставки. Новая посылка не доставлена;
команда 7 отмечает её доставленной. Просрочены только недоставленные посылки,
плановый срок которых строго раньше текущего местного системного времени.
Равенство срока и текущего времени ещё не считается просрочкой.

Массив посылок постоянно упорядочен по индексу получателя, затем по идентификатору.
Идентификаторы уникальны во всём отделении, даже при разных индексах получателя.
Добавление выполняет глубокое копирование посылки; исходный объект остаётся
у вызывающего кода. Удаление освобождает все поля выбранной посылки.
Функции обработки данных не выполняют ввод и вывод.

Доставленные и просроченные посылки выбираются в отдельный массив `MailView`.
В нём хранятся указатели на посылки; массив сортируется по времени создания,
при равенстве — по идентификатору. Основной массив при этом не меняется.
Память результата `post_select` освобождает вызывающий код через `free`.
Указатели из поиска и отчётов действительны до следующего изменения коллекции.
`post_destroy` удаляет посылки и массив; адрес самого отделения освобождает его владелец.

Валидация:

- Город и улица должны содержать хотя бы один непробельный символ; корпус может быть пустым.
- Дом и квартира — положительные значения `unsigned int`.
- Индекс — ровно 6 десятичных цифр, идентификатор — ровно 14. Ведущие нули сохраняются.
- Вес — конечное неотрицательное значение `double`, допускается ноль.
  При вводе используется десятичная точка; разрешена запись с `e`/`E`.
  Отрицательные числа, `NaN`, бесконечность, шестнадцатеричная запись отклоняются.
  Веса не сортируются и не сравниваются между собой; проверяются их конечность и знак.
- Даты — строго `dd:MM:yyyy hh:mm:ss`, годы 0001–9999, с проверкой числа дней
  в месяце и високосного года. Плановое вручение не раньше создания.
  Нельзя отметить доставленной посылку, время создания которой ещё не наступило.

## Задание 5

`task05.c` загружает студентов в динамический массив, предоставляет интерактивный
поиск и сортировку, дописывает выбранные отчёты в трассировочный файл.
Каждая структура `Student` содержит неотрицательный `unsigned int id`,
динамические строки имени, фамилии и группы, динамический массив из пяти
элементов `unsigned char` для оценок.

### Входной файл

Одна запись занимает одну строку, поля идут в следующем порядке:

```text
id name surname group grade1 grade2 grade3 grade4 grade5
```

Пример:

```text
3 Ivan Petrov FA201 5 4 5 4 5
0 Anna Ivanova "FA 202" 3 3 4 3 4
```

Пустые строки пропускаются. Пробелы и табуляции разделяют поля.
Для группы с пробелами используются двойные кавычки. Внутри кавычек
поддерживаются `\"` для кавычки и `\\` для обратной косой черты.
Переводы строк LF/CRLF и последняя строка без перевода строки допустимы.

Имена и фамилии — непустые строки только из `A–Z` и `a–z`. Группа должна
содержать хотя бы один непробельный символ; для неё допустим UTF-8.
Идентификатор лежит в диапазоне 0–`UINT_MAX`, оценки — 0–`UCHAR_MAX`
(на используемой платформе 0–255). Числа записываются десятичными цифрами,
ведущие нули допустимы. Нужно ровно пять оценок и девять полей в записи.
Нулевой байт, лишние поля, отрицательные числа, переполнение, неверные имена
или кавычки считаются ошибкой.

Идентификаторы могут повторяться: поиск по любому полю возвращает все
совпадения. Текстовый поиск чувствителен к регистру и использует полное
совпадение, а не подстроку.

### Функции обработки данных

```c
Status load_students(const char *path, Student **result, size_t *count);
Status sort_students(Student *students, size_t count, StudentComparator comparator);
Status find_students(const Student *students, size_t count, StudentField field,
                     unsigned int id, const char *text, StudentMatches *result);
Status student_average(const Student *student, double *result);
Status overall_average(const Student *students, size_t count, double *result);
Status select_above_average(const Student *students, size_t count, double epsilon,
                           StudentMatches *result, double *average);
Status matches_destroy(StudentMatches *matches);
Status students_destroy(Student **students, size_t *count);
```

Перед загрузкой указатель массива должен быть `NULL`, перед поиском и отбором
результат — `StudentMatches matches = {0};`. Все функции возвращают статус,
целевые результаты передают через параметры. В каждой записи должно быть
пять доступных элементов массива оценок. Загрузчик создаёт независимые
динамические строки и массив оценок для каждого студента.

Сортировка выполняется только `qsort` с переданным компаратором. Есть отдельные
компараторы по id, фамилии, имени и группе. Порядок возрастает; при равенстве
текстового ключа сравнивается id. Относительный порядок записей с одинаковыми
ключами не фиксируется.

`StudentMatches` содержит динамический массив указателей на найденные структуры.
`matches_destroy` освобождает только этот массив, не самих студентов.
Указатели результатов следует использовать до следующей сортировки или удаления
коллекции. `students_destroy` освобождает все поля студентов и основной массив.
Вычислительные функции не выполняют ввод и вывод.

Средний балл студента равен сумме пяти оценок, делённой на пять; общий средний
вычисляется по всем экзаменам всех студентов. При отборе используется условие
`средний студента - общий средний > epsilon`. Epsilon — положительный конечный
параметр функции; в диалоге используется `1e-9`. Сравнение выполняется через
масштабированные суммы в `long double`, без предварительного округления средних
до `double`. Для пустой коллекции общий средний не определён — возвращается
отдельный статус, диалог остаётся доступным.

### Запуск задания 5

В CLion перезагрузите CMake и выберите цель `task05`. Нужны ровно два аргумента:
путь к данным студентов и путь к трассировочному файлу.

Например, в поле Program arguments:

```text
/home/knrzev/CLionProjects/FA/FA_Lab3/tests/task05_students.txt /tmp/task05_report.txt
```

Пути с пробелами заключаются в двойные кавычки.
Трассировочный файл открывается в режиме добавления: прежние отчёты сохраняются.
Входной файл и трассировочный должны быть разными; одинаковые пути, символические
и жёсткие ссылки на входной файл отклоняются. Проверка ссылок использует `stat`
из POSIX, доступный в Linux.

Команды:

| Команда | Действие |
| --- | --- |
| 1 | Вывести всех студентов, оценки и средние баллы |
| 2 | Найти по одному из четырёх полей и вывести все совпадения |
| 3 | Отсортировать по одному из четырёх полей |
| 4 | Дописать в файл сведения всех найденных по id: фамилию, имя, группу, средний балл |
| 5 | Дописать фамилии и имена студентов со средним выше общего |
| 0 | Завершить работу |

Для команд 2 и 3 номера полей одинаковы: 1 — id, 2 — фамилия, 3 — имя,
4 — группа. В консольном поиске группа вводится целиком одной строкой,
без внешних кавычек. Команды и запрашиваемые значения вводятся отдельно,
каждое с новой строки.

Пример данных `tests/task05_students.txt` содержит четыре записи. Поиск id 3
даёт двух студентов; их средние — 4.6 и 4.4. Общий средний — 4.35,
выше него три студента. Готовый диалог находится в `tests/task05_example.txt`.

Из терминала:

```bash
cmake -S . -B build
cmake --build build
./build/task05 tests/task05_students.txt /tmp/task05_report.txt
./build/task05 tests/task05_students.txt /tmp/task05_report.txt < tests/task05_example.txt
ctest --test-dir build --output-on-failure
```

Для готового диалога в CLion включите Redirect input from и выберите
`tests/task05_example.txt`; два аргумента с путями данных и отчёта остаются обязательными.

Ошибочные команды и поисковые значения не завершают диалог. При неверных
входных записях загрузка отменяется целиком, трассировочный файл не открывается.
Ошибка памяти или ввода/вывода завершает программу с освобождением ресурсов.
Конец консольного ввода закрывает диалог. Открытые файлы закрываются, результаты
записи проверяются, после каждого отчёта выполняется сброс буфера файла.

Отдельно повторить проверки № 5: `python3 tests/test_task05.py`.
Глобальных переменных, `errno`, `goto`, комментариев в C-коде и принудительного
завершения из вспомогательных функций нет.
